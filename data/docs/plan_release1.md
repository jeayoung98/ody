## 3. 완성도 기준 (배포 전 검사표)

주변 탐색
- 카탈로그 곡 질의 → top-10, p50 < 20ms / p95 < 50ms (사전 계산 그래프 경로), 폴백 정확 kNN < 300ms
- 같은 녹음 접힘(τ_dup 1.66) · 같은 아티스트 ≤ 3 · 길이 규칙 · 표시 필터 · 제외(excluded) 곡 미노출
- 응답에 거리, depth-2 노드, 리프, "유사도 낮음" 플래그(10위 거리 > τ_far 4.91)
- 제목·아티스트 검색 진입: 한글·영문, 2자 이상, 결과 20개 이내

여정
- from/to 카탈로그 곡, 역 10개, 같은 canonical 제외, 아티스트 ≤ 2, 길이 규칙
- 끝점 거리 > 10.7 → 200 응답에 `reachable:false`, 이유 문자열
- 역마다 앞 역과 거리·진행도·노드; 방식 표기(`linear` / `axis`)
- p95 < 2s (직선 보간: 지점 10개 × 전곡 스캔 ≈ 1s; 느리면 faiss IVF 로 교체)

트리 탐색
- 노드 경로 → 자식 4개, 곡 수, 2D 중심(pc1, pc2), 대표곡 5(브릿지·인기 우선), 깊이 6 리프까지

데이터 트랙(Spark)
- 아티팩트 v2.2 를 Spark 파이프라인이 재현: 좌표·제외·리프 패리티 100%(오차 < 1e-4)
- manifest 에 입력 해시·규칙 해시·행 수·생성 시각, 버전 semver(v2.2.0)

## 4. 뒤처지면 자르는 순서 (위에서부터)

1. 원본 tar.zst Spark 적재(S0) — 기존 추출 Parquet 8.8GB 로 대체 (패리티는 그대로 성립). **추출 Parquet 의 HDFS 적재와 YARN 제출은 여기 포함되지 않는다** — 아래 참조
2. ANN(faiss) — 그래프 + 정확 kNN 폴백으로 충분
3. 축 우선 DP 옵션 — 직선 보간만 배포
4. 평가 잡 자동화 — 수동 실행
5. 대표곡·2D 중심 — 노드 자식·곡 수만
6. Spark 전곡 처리 — 표본 10만 행 패리티까지만 (클러스터 실행은 유지)

절대 자르지 않는 것: 제외 곡 미노출, 후처리 규칙, 끝점 상한, 패리티 테스트, **Spark·Hadoop 클러스터 실행**(D8).

D8 보충 — 프로젝트 요건상 Spark 와 Hadoop 을 모두 실제로 써야 한다. 그래서 잘리는 것은 **처리 범위**(원본 630GB, 전곡)이고 **실행 환경**이 아니다. 최소선은 추출 특징 8.8GB 를 HDFS 에 올리고 S2·S3 을 `spark-submit --master yarn` 으로 완주시키는 것이며, YARN application id 와 HDFS 경로·행 수를 `output/spark_run_*.json` 에 남긴다(스펙 20 AC0). 로컬 `pyspark local[8]` 결과는 이 요건을 충족하지 않는다.
