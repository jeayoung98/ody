# 17 pgvector 좌표 서빙 — plan

## 적재 경로
좌표 원본은 `serving/<version>/coords_v2.parquet` 다. 그걸 CSV 로 풀어 `COPY` 하는 게 가장 빠르다.
50만 행에 6초였으니 662만 행은 80초 안쪽이다. INSERT 문으로 넣지 않는다.

```
coords_v2.parquet  →  vec.csv (mbid, "[v1,...,v16]")  →  scp  →  COPY  →  CREATE INDEX
```

순서가 중요하다. **적재를 먼저, 인덱스를 나중에** 만든다. 인덱스가 있는 상태로 662만 행을 넣으면 훨씬 느리다.

CSV 는 pgvector 텍스트 표현을 그대로 쓴다. `[16.8063,-5.45127,...]` 형태이고 CSV 안에서는 큰따옴표로 감싼다.
값은 `%.6g` 로 찍는다. float32 유효자릿수를 넘지 않으면서 좌표 불변성(AC7)을 지킨다.

## 인덱스 파라미터
1차는 HNSW 기본값(`m=16`, `ef_construction=64`)으로 간다. 실측에서 recall@10 0.9995 가 나왔으므로
파라미터를 올릴 이유가 없다. 빌드 비용만 커진다.

IVFFlat 은 쓰지 않는다. 인덱스가 작지만(약 480 MB 추정) 재현율이 리스트 수에 민감하고
데이터가 늘면 재빌드해야 한다. HNSW 는 증분 삽입이 된다.

질의 시 `hnsw.ef_search` 기본값은 40 이다. 필터를 거는 질의에서만 올린다(스펙 경고 2).

## 후처리와의 관계
pgvector 는 **후보만 뽑는다.** 중복 접기·아티스트 상한·길이 규칙은 Backend 가 적용한다(D12). 임계값의 유일한 출처는 서빙 번들의 `postprocess_rules.json` 이다: τ_dup 1.6624 · artist_cap 3 · τ_far 4.912 · 길이 30~1200s. 전부 L2 거리 기준이다.
규칙 임계값이 `postprocess_rules.json` 에 있고 SQL 로 옮기면 두 벌이 되기 때문이다(규칙 9).

즉 흐름은 이렇다.
```
pgvector top-50  →  postprocess.apply_rules  →  top-10
```
Backend 가 직접 조회하는 경우에도 후처리는 AI 서비스가 하거나, 규칙을 그대로 옮긴 공용 라이브러리를 쓴다.
어느 쪽으로 할지는 Backend 담당과 정한다. **규칙을 두 곳에 손으로 베끼지 않는다.**

## 검증 방법
정답은 numpy 정확 kNN 이다. 구현은 삭제됐으므로(D12) 필요하면 `coords_v2.parquet` 를 읽어 임시 스크립트로 계산한다. 2026-09-10 실측 recall@10 0.9995 는 `output/pgvector_bench_2026-09-10.json` 에 있다.

```
무작위 200곡 → exact_knn(k=10) → 정답셋
             → pgvector top-10 → 대조 → recall@10
```

측정 스크립트는 `tests/bench_pgvector.py` 로 두고 결과를 `output/` 에 남긴다.
DB 접속 정보가 없는 환경에서는 skip 한다(`conftest.py` 의 fixture 방식과 동일).

## 재적재 전략
번들이 바뀌면(v2.2 등) 좌표가 바뀐다. 방법 두 가지.

1. **테이블 교체** — `track_vector_new` 에 적재·인덱싱 후 트랜잭션 안에서 이름을 바꾼다. 다운타임이 거의 없다.
2. **제자리 UPDATE** — 662만 행 UPDATE 는 죽은 튜플이 대량 생겨 VACUUM 이 필요하다. 권하지 않는다.

1번으로 간다. 롤백은 이전 테이블을 지우지 않고 며칠 두는 것이다.

## 리스크
- **인덱스 빌드가 예상보다 오래 걸린다.** 외삽이 선형 가정인데 HNSW 는 초선형이다. 인프라 상향 전에는 시작하지 않는다.
- **서브쿼리 함정을 Backend 가 밟는다.** 조용히 틀린 이웃이 나가므로 테스트로 못 잡을 수 있다. 연동 문서에 크게 적고, 리뷰에서 확인한다.
- **필터 질의가 덜 반환한다.** 0.7.0 제약이다. 부분 인덱스로 대응하고, 안 되면 버전 상향을 요청한다.
- **후처리가 두 벌이 된다.** Backend 가 SQL 로 규칙을 다시 짜면 임계값이 어긋난다. 공용 경로를 강제한다.
