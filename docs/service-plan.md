# CRATE 음악 지도 서비스 기획서

> 출처: Notion 「서비스 기획서」 스냅샷 (최종 편집 2026-09-02). 정본은 Notion.

## 1. 문제 정의

사용자는 자신이 어떤 음악을 좋아하는지는 알고 있지만, 그 취향이 음악 전체에서 어디쯤에 있는지는 알기 어렵다. 기존 스트리밍 서비스의 추천은 결과 목록만 제시할 뿐, 그 곡이 왜 추천되었는지와 사용자가 현재 어느 지점에 있는지를 함께 보여주지 않는다.

추천의 근거가 보이지 않으면 사용자는 결과를 받아들이거나 넘기는 것 외에 할 수 있는 일이 없다. 추천 범위가 좁게 느껴져도 어느 방향으로 넓혀야 할지 지정할 방법이 없고, 낯선 장르는 진입점이 없어 시도 자체가 어렵다. 장르 이름만으로는 두 음악이 실제로 얼마나 다른지 판단할 수 없으며, 슈게이즈와 드림팝의 차이를 글로 설명한 문서를 읽어도 소리로 확인하기 전까지는 감각적으로 이해되지 않는다.

또한 음악 취향은 다른 사람과 공유할 때 확장되는 경우가 많지만, 기존 서비스에서 다른 사용자의 취향을 확인하는 방법은 완성된 플레이리스트를 열람하는 수준에 그친다. 지금 나와 비슷한 음악을 듣고 있는 사람이 누구인지, 그 사람이 어디를 탐색하고 있는지는 알 수 없다.

본 서비스는 공개 음악 데이터를 기반으로 약 920만 곡을 소리의 성질에 따라 하나의 좌표 공간에 배치하고, 사용자가 자신의 위치를 확인한 뒤 원하는 방향으로 직접 탐색하며 같은 공간에 있는 다른 사용자와 취향을 공유할 수 있도록 하는 것을 목표로 한다.

## 2. 타깃 사용자

본 서비스의 핵심 사용자는 추천받은 음악을 그대로 듣는 데 그치지 않고, 추천의 근거를 확인하며 원하는 방향을 직접 지정하고 싶은 사용자이다.

- 좋아하는 스타일을 더 깊이 파고들고 싶은 사용자
- 최근 듣는 음악이 비슷하다고 느껴 낯선 영역으로 이동하고 싶은 사용자
- 추천된 곡이 자신의 취향과 어떤 관계에 있는지 확인하고 싶은 사용자
- 장르 간의 관계와 차이를 실제 소리로 확인하고 싶은 사용자
- 특정 분위기의 플레이리스트를 직접 구성하려는 사용자
- 자신의 음악 취향이 어떤 특성을 가지는지 확인하고 싶은 사용자
- 취향이 비슷한 다른 사용자를 발견하고 소통하고 싶은 사용자

## 3. 서비스 목표

추천 결과를 목록으로만 전달하는 방식에서, 추천이 이루어지는 공간 전체를 지도로 보여주고 사용자가 그 위에서 목적지를 직접 정하는 방식으로 전환한다.

- **3.1 취향의 가시화** — 취향을 지도 위의 좌표로 표현하여 자신이 어느 지점에 있는지 눈으로 확인
- **3.2 방향의 선택권** — 다음에 들을 곡을 서비스가 아니라 사용자가 목적지를 탐색·설정하고 경로를 따라 이동
- **3.3 깊이 탐색** — 장르 계층과 음향 특성 계층을 단계적으로 제공
- **3.4 너비 탐색** — 원하는 분위기와 벡터 임베딩상 가까운 곡을 함께 제시 (※ 장르 조건 병용 여부는 추가 논의)
- **3.5 소리를 통한 확인** — 수치·그래프가 아니라 실제 음원 미리듣기로 차이를 직접 판단
- **3.6 취향 기반의 사용자 연결** — 같은 좌표 영역 사용자를 서로 노출하여 가벼운 소통과 함께 탐색

## 4. 서비스 한 줄 소개

약 920만 곡을 소리의 성질에 따라 하나의 지도 위에 배치하고, 사용자가 자신의 위치에서 원하는 지점까지 탐색하면서 같은 공간에 있는 다른 사용자와 음악을 공유할 수 있는 음악 탐색 서비스.

## 5. 핵심 기능

### 5.1 회원가입 및 온보딩
회원가입 후 온보딩으로 선호 정보를 입력하고, 이를 기반으로 지도 위의 초기 좌표를 부여받는다. (※ 수집 정보 종류·방식 추가 논의)

### 5.2 지도 기반 추천 탐색
지도에서 음악 전체 분포를 확인하고 단계적으로 확대하며 탐색한다. 계층 순서:
- 대분류 장르 → 소분류 장르 → PC 레이어 1, 2, 3 …

상위 두 단계는 장르 태그 기준, 그 아래는 음향 특성의 주성분 기준. **주성분은 전체 곡 대상 1회 계산 후 고정**하며, 장르 단계는 좌표 공간에서 표시할 곡을 걸러내는 필터로 동작한다. PC 레이어는 설명력이 큰 순서로 적용된다. 축은 수치가 아니라 일상적 표현으로 제공(예: "밤에 혼자 듣는 음악 ↔ 운동할 때 트는 음악").

### 5.3 주변 탐색
선택한 조건에 가까운 음악을 지도에 표시. 기준은 벡터 임베딩 근접도 중심. (※ 장르 조건 병용 여부 추가 논의)

### 5.4 여정 생성
출발·도착 지점을 선택하면 두 지점 사이를 지나는 곡을 순서대로 제공. 경로는 두 지점을 일정 간격으로 나눈 뒤 각 지점에서 가장 가까운 곡을 선택해 구성. (※ 지정 단위 장르/곡 추가 논의)

### 5.5 주변 친구
지도상 가까운 좌표의 다른 사용자를 표시(물리적 거리 아님). 같은 영역 사용자에게 이모지/짧은 메시지 반응 가능. 계정 공개/비공개 설정 가능(비공개는 목록 미표시).

### 5.6 따라가기
주변 친구의 탐색을 실시간으로 함께 따라감. 상대의 화면 이동이 그대로 반영되고, 따라가는 동안 직접 조작하지 않고 관찰. 해제 시 해제 시점 위치 유지. 상대 접속 종료·비공개 전환 시 자동 종료. 한 사용자를 여러 명이 동시에 따라갈 수 있고 인원 수 표시.

### 5.7 랭킹
플레이리스트 랭킹 / 사용자 랭킹. (※ 집계 기준 추가 논의: 좋아요/스크랩/조회/팔로워/탐색 영역 수)

### 5.8 음악 상세
곡 선택 시 아티스트·발매 연도·장르·지도상 위치 등 표시, 미리듣기 재생·플레이리스트 추가 제공.

### 5.9 피드
프로필 / 팔로우·팔로잉 목록 / 접속 여부 / 팔로우 사용자 접속 시 현재 탐색 위치로 이동 / 플레이리스트 목록 / 좋아요·스크랩.

## 6. 사용자 시나리오

### 6.1 지도를 탐색하는 사용자
회원가입·온보딩 → 초기 좌표 생성 → 대분류 장르 확인 → 소분류 진입 → PC 레이어로 영역 축소 → 축 라벨 확인 → 곡 선택·상세 → 미리듣기·플레이리스트 추가.

### 6.2 경로를 지정하여 이동하는 사용자
로그인 → 현재 위치를 출발점 지정 → 낯선/깊은 지점을 도착점 지정 → 여정 생성 → 두 지점 등분·최근접 곡 선택으로 경로 구성 → 경로·경유 영역 확인 → 순차 미리듣기 → 플레이리스트 저장.

### 6.3 다른 사용자와 함께 탐색하는 사용자
주변 친구 목록 확인 → 같은 영역 사용자에 이모지 반응 → 상대 응답 → 따라가기 시작 → 실시간 동반 이동·재생 확인·반응 → 해제 후 자신의 탐색 이어감.

## 7. MVP 범위

### 7.1 포함
회원가입·로그인, 온보딩 선호 입력, 초기 좌표 생성, 지도 화면, 대·소분류 장르 계층 탐색, PC 레이어 탐색, 축 라벨, 주변 탐색, 곡 검색, 음악 상세, 미리듣기, 플레이리스트 생성·곡 추가, 여정 생성, 경로 시각화, 주변 친구 목록, 접속 여부, 반응하기, 따라가기, 계정 공개/비공개, 마이페이지.

### 7.2 제외
프로필·피드, 팔로우/팔로잉, 좋아요·스크랩, 랭킹, 음원 저장·스트리밍, 1:1 채팅, 외부 플레이리스트 내보내기, 신곡 실시간 유입, 취향 변화 연대기, 청취 밀도 히트맵, 알림, 사용자 등급. (프로필·피드·팔로우·좋아요·스크랩은 하나의 소셜 묶음이라 함께 제외; MVP는 반응하기·따라가기만으로 사용자 연결 검증)

### 7.3 핵심 검증 목표 (발췌)
- 장르 계층이 데이터에서 자동 유도되는가
- 전체 곡 기준 고정 주성분이 세부 영역에서도 곡을 의미 있게 구분하는가
- 좌표 기반 유사곡 검색이 무작위보다 유의미하게 정확한가
- PC 레이어 마지막 단계까지 각 영역에 충분한 곡이 남는가
- 생성 경로의 곡 간격이 균등하고 흐름이 자연스러운가
- 따라가기에서 인솔자 화면 이동이 지연 없이 전달되는가
- 노드 수 증가에 따라 처리 시간이 실제로 단축되는가

## 8. 운영 정책 (초안)

- **음원**: 음원 파일 미저장, 외부 링크 재생만, 미리듣기 없는 곡은 재생 불가 안내, 비상업적 운영
- **데이터 출처/갱신**: 공개 DB 사용·출처/라이선스 명시, 좌표 변환은 1회 학습 후 고정, 장르 계층·영역 분할은 주 1~2회 재계산
- **좌표 신뢰도**: 음향 분석 완료 곡과 장르 추정 곡 구분, 신뢰도 낮은 영역 표시, 저신뢰 곡은 미분류로 분리 후 재처리
- **계정 공개 범위**: 기본 비공개, 비공개는 주변 친구·접속 표시 제외, 공개는 따라가기 허용, 노출은 표시명+좌표 영역까지
- **반응하기**: 정해진 이모지만, 반복 전송 제한, 수신 차단 가능, 신고 누적 시 전송 제한
- **따라가기**: 공개 계정만, 인솔자 개별 해제 가능, 비공개 전환·접속 종료 시 자동 종료, 동시 인원 상한
- **사용자 데이터**: 온보딩 정보는 좌표 생성·추천 목적만, 본인 삭제 가능, 탈퇴 시 연결 데이터 삭제, 물리적 위치 미수집

## 9. 기술 가능성 (요약)
- **좌표 산출**: 곡당 수천 음향 측정값 → 의미 항목 선별 → 차원 축소로 소수 좌표. 화면 두 축은 해석 가능한 원측정값(템포·밝기 등)
- **장르 계층 유도**: 장르 태그 동시 출현 패턴 분석으로 상위/하위 장르 관계 자동 추출, 좌표 불변·필터로 사용
- **PC 레이어**: 전체 곡 대상 PCA 1회 후 고정, 설명력 순 적용, 진입 경로 무관하게 같은 곡은 같은 위치
- **분산 처리**: 저장(HDFS/컬럼 포맷), 배치(Spark), 실시간(Kafka+Spark Structured Streaming), 서빙(RDB+인메모리 캐시)
- **실시간 접속/반응**: 접속 상태·좌표는 인메모리 유지·TTL 만료, WebSocket 통신, 좌표 구간 단위 조회, 반응은 일정 기간 후 삭제
- **따라가기**: 인솔자 단위 구독 채널에 이동 이벤트 발행, 좌표+노드 식별자만 담아 경량화, 재연결 시 현재 위치 동기화

## 10. 역할 분담 (기획서 기준)
- **프론트엔드**: 로그인·온보딩·지도·좌표 렌더링·계층 탐색·주변 탐색·검색·상세·미리듣기·여정/경로·주변 친구/반응·따라가기·플레이리스트·마이페이지·API 연동
- **백엔드**: 인증·온보딩 좌표 생성·지도 노드 조회·곡 상세·유사곡/주변 탐색·경로 생성·플레이리스트·접속/주변 사용자·반응 전달·따라가기 세션·공개 범위·파이프라인 산출물 적재/캐시·예외/로그
- **AI**: 해당 없음 (신호처리·통계로 축·계층 산출). 향후 추천 고도화 시 담당
- **데이터**: 원본 수집·품질 검증·중복 제거·항목 선별·좌표 변환 학습/고정·전체 좌표 산출·장르 계층 유도·PC 레이어 생성·검색 정확도/처리량 측정
- **기획/공통**: 요구사항·MVP 범위·온보딩 항목·주변 탐색 조건·여정 단위·PC 단계 수 확정, 시나리오·기능 명세·화면 흐름·와이어프레임·API 검토·정책·축 라벨·테스트 시나리오·발표 준비
