# 001. 파고든 겹이 화면을 안 채우던 문제

- 이슈: S15P21A405-259
- 커밋 / MR: `cc80d49` · MR !96 (261 과 함께 올라감)
- 날짜: 2026-09-12

## 증상

지도는 "돋보기로 확대해 들어간다"는 컨셉이다. 한 겹 파고들면 **그 구역이 확대돼 화면을 채워야** 하는데,
실제로는 파고들 때마다 상주 곡이 화면 가운데 **작은 별 뭉치 하나**로 모이고 주변은 빈 하늘이었다.
사용자 표현: *"멀리 떨어진 별뭉치면 안 된다는 거임. 별들이 꽉차있어야함 화면에."*

## 측정 — 개선 전

| 지표 | 값 |
| --- | --- |
| 상주 1,000곡 중 화면 안에 들어온 비율 | **40%** |
| 상주곡 3~97분위 상자가 차지한 화면 폭 | 20% |
| 상주곡 3~97분위 상자가 차지한 화면 높이 | 44% |

**측정 방법**: 지도에서 한 겹 파고든 직후(카메라 이동 전) 브라우저 콘솔에서 엔진 상태를 읽었다.

```js
const e = window.__odyEngine;
let residents = 0;
for (let i = 0; i < e.N; i++) if (e.subset[i]) residents++;
({ residents, inView: e.countInView(), ratio: e.countInView() / residents });
```

분위수 상자는 `songs[i].pc[2l], pc[2l+1]` 를 모아 3·97분위를 잡고 화면 폭·높이로 나눴다.

## 원인

`fitCam()` 이 **모든 겹에 레이어 0 의 맞춤 방식**을 쓰고 있었다
([map-engine.ts](../../src/components/map/engine/map-engine.ts) `fitRadial`).

```
배율 = (화면 짧은 변 × 0.44) / (내 곡 기준 거리의 97분위)
```

두 가지가 겹쳤다.

1. **거리 분위수는 꼬리에 끌려간다.** 97분위까지 화면에 넣으려니 멀리 떨어진 소수의 곡 때문에
   배율이 작아지고, 정작 곡이 몰려 있는 알맹이는 가운데 작게 모인다.
2. **기준점이 내 곡이다.** 내 곡이 무리 가장자리에 있으면 반지름의 절반이 빈 하늘에 쓰인다.

레이어 0(전 우주)에서는 "내 위치 중심으로 우주를 본다"가 맞는 연출이라 문제가 없었지만,
파고든 겹은 **"이 영역을 확대해 들어왔다"** 라서 들어온 영역 전체가 보여야 했다.

## 조치

겹에 따라 맞춤 방식을 갈랐다.

- **레이어 0**: 그대로 `fitRadial` (내 곡 중심, 거리 97분위). 연출 의도가 다르다.
- **파고든 겹**: `fitBox` 로 교체 — 가로·세로를 **따로** 잰 분위수 상자(양 끝 3% 컷)가
  화면의 90%를 차지하는 배율을 잡고, 그 상자의 한가운데를 본다.

```
배율 = min( (화면폭 × 0.9) / 상자폭, (화면높이 × 0.9) / 상자높이 )
```

같이 바꾼 것: 파고든 겹에서는 **진입 배율이 곧 축소 한계**가 되도록 했다(`deepZoomOutRatio: 1`).
그 아래로 줄이면 빈 우주만 더 보이고, 그건 "떠오르기"로 처리할 동작이기 때문이다.
→ 들어온 그 화면이 **그 겹의 최대 줌아웃**이 된다.

버린 대안: 거리 분위수를 97 → 80 으로 낮추는 것. 배율은 커지지만 **기준점이 내 곡이라는 문제**가
남아서, 내 곡이 가장자리일 때 여전히 절반이 비었다.

## 측정 — 개선 후

같은 방법으로 다시 쟀다. 레이어 0 → 1 파고든 직후, 카메라를 건드리지 않은 상태다.

| 지표 | 개선 전 | 개선 후 | 변화 |
| --- | --- | --- | --- |
| L1 상주곡 중 화면 안 비율 | 40% (400/1,000) | **96.3%** (963/1,000) | **+56%p** |
| L2 상주곡 중 화면 안 비율 | 미측정 | **96.1%** (124/129) | — |
| 진입 시 `zoomK` (진입 배율 대비) | 1 | 1 | 변화 없음 (의도) |

L2 값은 좌하단 계기판의 `이 겹 129곡 / 화면 안 124곡` 표기로도 확인했다.

## 남은 것

- **꼬리는 여전히 잘린다.** 양 끝 3%는 일부러 화면 밖이다 — 전부 넣으려면 다시 알맹이가 작아진다.
  "간당간당하게 꽉 찬다"가 목표라 3%는 의도적 트레이드오프다.
- 레이어 0 은 그대로 두었다. 여기도 같은 불만이 나오면 `fitBox` 를 확장하면 되지만,
  전 우주는 "내 위치 중심"이 연출 의도라 지금은 건드리지 않는다.
- FPS·그리기 시간은 이 변경으로 달라지지 않는다 (그리는 곡 수가 아니라 카메라 배율만 바뀐다).
  프레임 비용은 [`PERF-LOG.md`](../../PERF-LOG.md) 쪽에서 따로 본다.
