# 001. 겹을 옮기면 "내 위치로 가기"가 엉뚱한 곳으로 간다

- 이슈: S15P21A405-263
- 커밋 / MR: `d02fe6e` `186f4b8` `b393264` · MR !98
- 날짜: 2026-09-12

## 증상

하단 플레이바의 **내 위치로 가기**(MAP-08)를 눌러도 '나' 표식이 화면 가운데로 오지 않는다.

1. 지도에서 곡을 눌러 재생한다 → '나'가 그 별로 날아간다
2. 휠로 한 겹 파고든다
3. **내 위치로 가기**를 누른다
4. → 카메라는 움직이는데 '나'는 화면 가운데에 없다

두 번째 경로도 똑같이 안 됐다: 주변 탐색을 열고 → 이웃 곡을 누르고 → 주변 탐색을 닫고 → 내 위치로 가기.

## 처음 의심한 것 (틀렸다)

버튼이 안 먹는 줄 알고 `goHome()` 의 가드부터 봤다 — 오버레이 중이면 `"overlay"`, 전환 중이면 `"queued"` 를
돌려주는 분기들이다. **여기는 멀쩡했다.** 레이어 0 에서 화면을 밀고 눌러 보니 정확히 가운데로 왔다
(`meScreen (474, 367)` == `freeCenter (474, 367)`).

그래서 "버튼이 안 먹는다"가 아니라 **"버튼은 제자리로 가는데 '나'가 거기 없다"** 로 문제를 다시 세웠다.

## 증거

곡 하나를 재생하고 겹을 오르내리면서 `myId`(= '나'인 곡)와 `home.musicId`(= 돌아갈 곡)를 같이 찍었다.

```js
const e = window.__odyEngine;
({ myId: e.myId, playingId: e.playingId, home: e.home, alive: e.isAlive(e.myId) });
```

| 시점 | `myId` | `home.musicId` |
| --- | --- | --- |
| 곡 재생 직후 | 4214989 | 4214989 |
| 한 겹 파고든 뒤 | **2375108** | 4214989 |
| 내 위치로 가기 후 (L0 복귀) | **5096938** | 4214989 |

`myId` 가 두 번 바뀌었다. 그 상태에서 '나' 화면 좌표는 `(612, 426)`, 지도 영역 중앙은 `(474, 367)` —
어긋난 거리 그대로였다.

## 원인

[`map-engine.ts` `setLayerSongs()`](../../src/components/map/engine/map-engine.ts)

```ts
// 내 곡이 이 겹에 없으면 가장 가까운 상주 곡으로 옮긴다 (카메라 기준점이 있어야 한다)
if (!ns[this.index.get(this.myId!)!]) this.myId = this.nearestIn(ns, this.myId!, layer);
```

겹마다 서버가 상주 집합(top-k)을 내려주는데, 내 곡이 그 집합에 없을 수 있다. 그때 **카메라 맞춤(`fitCam`)의
기준점**을 잃지 않으려고 `myId` 를 가까운 상주 곡으로 바꿔치기하고 있었다. 의도는 맞았지만 **되돌리지 않았다.**

결과적으로 두 값이 갈라졌다.

- 카메라는 `home.musicId`(내가 재생한 곡) 기준으로 움직인다 → 제자리로 간다
- '나' 표식은 `myId` 기준으로 그려진다 → 남의 곡 위에 있다

덤으로 `myId` 는 `localStorage` 에 저장된다. 그래서 **틀어진 값이 다음 세션까지 따라왔다** —
새로고침 직후 '나'가 엉뚱한 곡 위에 있는 것도 같은 뿌리다.

### 두 번째 원인 (주변 탐색 경로)

주변 탐색에서 고른 이웃 곡은 그 겹 상주 집합 밖이라 `travelTo()` 가 **`home` 을 설정하기 전에 빠져나갔다.**
그래서 내 위치로 가기가 한참 전에 재생한 딴 곡으로 갔다. 게다가 `meArrow()` 와 매 프레임 가운데 고정 로직이
'나'의 자리를 **재생 중인 곡** 기준으로 잡고 있어서, 가운데로 데려다 놔도 곧바로 다시 끌려갔다.

## 조치

1. **`myId` 는 움직이지 않는다.** 겹 맞춤에만 쓰는 기준 곡을 `fitAnchor()` 로 따로 구한다 —
   내 곡이 상주하면 내 곡, 아니면 가장 가까운 상주 곡. `setLayerSongs` · `descend` · `resize` 가 이걸 쓴다.
2. **이 겹에 없는 곡을 재생해도 `home` 을 기억한다.** 그래야 돌아올 곳이 지금 곡이다.
3. **내 위치로 가기로 데려온 곡은 그 겹에 못 박는다**(`pinned`). 안 그러면 서버 상주 집합 응답이
   도착하는 순간 도로 빠져서 다시 가생이 화살표가 된다 — 겹을 넘어갔다 오는 경로에서 실제로 재발했다.

MAP-08 이 정한 "재생 곡이 이 겹에 없으면 '나'는 따라가지 않는다"는 그대로 지켰다.
그 경우 표식은 글씨 없이 **가생이의 옅은 점 + 화살촉**으로만 알린다.

## 확인

| 시나리오 | 결과 |
| --- | --- |
| 곡 재생 → 한 겹 파고들기 | `myId` 유지 (4891330), 내 곡 비상주여도 안 바뀜 |
| 그 상태에서 내 위치로 가기 | L0 복귀, '나'가 지도 영역 중앙과 **오차 0px** |
| 주변 탐색 → 이웃곡 재생 → 닫기 → 화면 밀기 → 내 위치로 가기 | '나' (922, −147) → 중앙, **오차 0px** |
| 주변 탐색 이웃곡 재생 → 파고들기 → 내 위치로 가기 | L0 복귀, 상주로 편입돼 표식이 중앙에 그려짐 |
| 주변 탐색이 열린 채로 누름 | 토스트 `주변 탐색·별자리 뷰를 닫고 눌러주세요` (의도대로 차단) |

오차는 `e.worldToScreen(e.me.x, e.me.y)` 와 `e.freeRect()` 의 중심 차이로 쟀다.

## 배운 것

**"같은 것을 가리키는 변수가 둘"** 이면 언젠가 갈라진다. 여기서는 `myId`(표식) / `playingId`(재생 곡) /
`home.musicId`(돌아갈 곡) 셋이 같은 개념을 나눠 들고 있었고, 하나만 조용히 바뀌면서 증상이 "버튼이 안 먹는다"로
보였다.

다음에 "눌렀는데 아무 일도 안 난다"를 만나면 **동작을 먼저 의심하지 말고, 눈에 보이는 것과 코드가 믿는 것이
같은지부터 찍어 본다.** 여기서도 카메라는 처음부터 정확히 제자리로 가고 있었다.
