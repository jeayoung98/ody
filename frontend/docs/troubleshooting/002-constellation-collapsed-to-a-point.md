# 002. 별자리 뷰가 한 점으로 뭉친다

- 이슈: S15P21A405-264
- 커밋 / MR: `c5c57c5` · MR !101
- 날짜: 2026-09-12

## 증상

여정(JOURNEY-01) 경로를 만들면 별자리 오버레이 뷰(PATH-01)가 자동으로 켜진다.
22곡짜리 경로인데 화면에는 **별 몇 개가 겹쳐 있는 작은 덩어리** 하나만 보였다.

사용자 표현: *"여정에서 별자리뷰 완전 하나로 뭉쳐있는데, padding만 잡아두고 그 사이에 펼쳐서 보여줘."*

## 처음 의심한 것 (절반만 맞았다)

배치 배율 문제로 봤다. `constellationPos()` 가 정규화 좌표에 **고정 반지름**을 곱하고 있었기 때문이다.

```ts
const R = Math.min(f.x1 - f.x0, f.y1 - f.y0) * CONSTELLATION.radiusRatio; // 0.4
const tx = f.cx + p.x * R * o.zoom + o.dx;
```

점들이 -1~1 안에서 가운데 몰려 있으면 몰린 채로 작게 나온다 — 맞는 지적이지만, **이것만으로는
"한 덩어리"가 설명되지 않았다.** 고쳐도 여전히 뭉쳐 보여서 상태를 직접 찍어 봤다.

## 증거

```js
const e = window.__odyEngine, c = e.constellation;
({ n: c.ids.length, box: c.box, sample: c.layout.slice(0, 4) });
```

```json
{
  "n": 4,
  "box": { "x0": 0, "x1": 0, "y0": 0, "y1": 0 },
  "sample": [
    { "musicId": 3725330, "x": 0, "y": 0 },
    { "musicId": 4410203, "x": 0, "y": 0 },
    { "musicId": 3352984, "x": 0, "y": 0 },
    { "musicId": 3984920, "x": 0, "y": 0 }
  ]
}
```

두 가지가 한꺼번에 보였다.

- **좌표가 전부 `(0, 0)`** — 배율이 문제가 아니라 배치 자체가 한 점이었다. 어떤 배율을 곱해도 한 점이다.
- **22곡 중 4곡만** 별자리에 들어가 있었다 (`n: 4`).

## 원인

### (a) 배치 계산이 실데이터 곡을 모른다

배치는 `POST /api/constellations/layout` 가 만드는데 **아직 목**이다(BACKEND-NOTES A-9).
목은 좌표를 `mocks/songs.ts` 에서 찾는다.

```ts
const rows = musicIds.map((id) => songById(id)?.pc ?? new Array(16).fill(0));
```

그런데 여정 경로는 **배포 백엔드**에서 오는 곡이라 목이 모른다 → 전부 0 벡터 → 간이 PCA 가 한 점으로 붕괴.
`?? new Array(16).fill(0)` 폴백이 "모르는 곡"을 조용히 원점으로 보내고 있었다.

### (b) 경로 곡이 엔진에 없다

`enterConstellation()` 은 `ids.filter((id) => this.index.has(id))` 로 거른다. 경로 곡은 지도 상주 집합
(레이어 0 = 1,094곡) 밖일 수 있어서 22곡 중 18곡이 이 단계에서 사라졌다.

### (c) 그리고 처음 의심한 고정 반지름

(a)(b)를 고쳐도 배치가 납작하면 화면을 못 채운다. 이건 진짜 문제가 맞았다.

## 조치

1. **좌표를 실어 나른다.** 백엔드 여정 응답이 이미 `path[].location`(pc1~16)을 주고 있어서
   `JourneyStop.pc` 로 받아, 배치 요청에 `points: [{musicId, pc}]` 로 함께 보낸다.
   **계약은 `musicIds` 만이다** — 백엔드가 A-9 를 구현하면 이 필드는 무시하면 된다.
2. **경로 곡을 엔진에 편입한다.** 별자리 진입 전에 `engine.adopt(points)`.
3. **배치를 화면에 맞춰 편다.** 고정 반지름 대신 배치 자체의 바운딩박스를 재서, 여백만 남기고 꽉 차게.
   여백은 고정 px 이 아니라 **비율(7%, 최대 64px)** 로 뒀다 — 우측 패널이 열려 영역이 좁을 때
   고정 64px 씩 빼면 남는 폭의 40% 가 여백이 되어 넓힌 의미가 없어진다.

가로·세로는 **같은 배율**을 쓴다. PATH-01 이 "플리 모양(예: 강아지)이 상품으로 성립"한다고 정해서,
축마다 다른 배율로 늘리면 모양이 찌그러진다.

## 확인

| 지표 | 개선 전 | 개선 후 |
| --- | --- | --- |
| 별자리에 들어간 곡 수 | 4 / 22 | **22 / 22** |
| 배치 바운딩박스 | `x [0, 0]`, `y [0, 0]` | `x [−1, 0.52]`, `y [−0.40, 0.21]` |
| 배치 배율 `s` | (한 점이라 무의미) | 134 → **168** (여백을 비율로 바꾼 뒤) |

## 배운 것

**"모르면 0"** 폴백은 조용해서 위험하다. `songById(id)?.pc ?? new Array(16).fill(0)` 은 에러도 경고도
없이 전부 원점으로 보냈고, 화면에는 "뭉쳐 보인다"는 **다른 문제처럼** 나타났다.

목과 실데이터가 섞이는 구간에서는 **입력이 비었을 때 조용히 기본값으로 가지 말고 티를 내야 한다.**
그리고 "작게 보인다" 같은 증상은 배율부터 보기 쉬운데, **입력값을 먼저 찍어 보는 게 빨랐다.**
