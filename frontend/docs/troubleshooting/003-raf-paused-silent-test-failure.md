# 003. 브라우저 패널이 숨으면 테스트가 조용히 실패한다

- 이슈: S15P21A405-215 (계측) 외 다수
- 날짜: 2026-09-10 ~ 2026-09-12
- 코드 변경 없음 — **측정·테스트 환경의 함정**

## 증상

지도 엔진을 브라우저에서 검증할 때, 실패가 **실패로 나타나지 않았다.**

- 성능 계측 스크립트를 돌렸는데 FPS·프레임 간격이 안 나왔다 (에러는 없었다)
- 휠 확대를 태웠는데 `wheel()` 이 `"blocked"` 만 돌려줬다
- 겹 전환 애니메이션이 **145초 동안 진행 중**이었다
- 엔진 `time` 이 계속 `0` 이었다

전부 "틀린 값"이 아니라 **"값이 안 변함"** 이라, 코드 버그처럼 보였다.

## 처음 의심한 것 (틀렸다)

- 휠 게이트 조건이 잘못됐나 → 조건식을 몇 번 고쳤다. 아니었다
- 모프 타이머가 멈췄나 → `performance.now()` 는 잘 흐르고 있었다

## 증거

엔진 시계와 진행 중인 애니메이션의 경과 시간을 같이 찍었다.

```js
const e = window.__odyEngine;
({ time: e.time, anim: e.anim && (performance.now() - e.anim.t0) / 1000 });
// → { time: 0, anim: 145.2 }
```

`time` 이 0 인데 애니메이션 경과는 145초. **프레임 루프가 한 번도 안 돌았다**는 뜻이다.
엔진 `time` 은 `requestAnimationFrame` 콜백에서만 증가한다.

## 원인

브라우저 패널이 **숨겨진 상태**였다. 브라우저는 보이지 않는 문서에서 `requestAnimationFrame` 을
멈춘다(throttle to zero). 그래서:

- `frame()` 이 안 돌아 `project()` · `pickRepresentatives()` 가 갱신되지 않는다
  → `e.pos`, `e.visible`, `e.chosen` 이 **전부 과거 값**이다
- 모프가 진행되지 않아 `anim` 이 영원히 남는다
  → `descend()` · `wheel()` 의 `if (this.anim) return` 가드에 계속 걸린다
- 계측 스크립트가 재는 FPS 는 0 인데, **0 이 아니라 "못 잼"으로 나온다**

`PERF-LOG.md` 첫 두 행에도 같은 흔적이 남아 있다
(`rAF 미동작으로 프레임·그리기 무효`, `탭_숨김이었나: true`).

## 조치

코드는 안 고쳤다. **검증 방법을 바꿨다.**

1. **엔진 상태를 읽기 전에 프레임이 돌고 있는지 확인한다.** `e.time` 이 증가하는지가 가장 싼 확인이다.
2. **실제 입력 액션(스크롤·클릭·스크린샷)으로 구동한다.** 스크린샷을 찍으면 패널이 살아나므로,
   확인 사이사이에 스크린샷을 끼워 프레임을 계속 돌린다.
3. **프레임과 무관한 것은 순수 계산으로 검증한다.** 예: 파고들기 범위는 화면을 보지 않고
   `drillBox()` / `countInBox()` 를 직접 불러 값으로 확인했다.
4. 계측은 **창이 실제로 화면에 보이는 상태에서만** 돌린다 (`scripts/README.md` 에 이미 명시돼 있다).

## 확인

프레임이 도는 상태에서 같은 시나리오를 다시 돌리면 값이 정상으로 흐른다.

| 항목 | 숨김 상태 | 보이는 상태 |
| --- | --- | --- |
| `e.time` | `0` (고정) | 증가 |
| 겹 전환 `anim` | 145초째 진행 중 | 1초 뒤 `null` |
| `wheel()` | 항상 `"blocked"` | 정상 확대 / 게이트 개방 |

## 배운 것

**캔버스 앱의 자동 검증에서는 "값이 안 변한다" 를 버그로 읽기 전에 프레임 루프부터 의심한다.**
rAF 정지는 예외도 경고도 없이 시스템 전체를 "정지된 과거"로 만들어서, 어느 계층을 찍어 봐도
그럴듯하게 틀린 값이 나온다.

한 줄 확인으로 끝난다: `window.__odyEngine.time` 이 증가하는가.

덤으로, 이 함정 때문에 **엔진 상태를 직접 건드려 테스트하는 습관**도 위험하다는 걸 같이 배웠다.
`e.cam` 을 직접 바꿔 놓고 복원했는데, 프레임이 안 돌아 `e.pos`(화면 좌표)가 갱신되지 않는 바람에
잘못된 결론을 냈다. 이후로는 상태를 **읽기만** 하고, 구동은 실제 입력으로 한다.
