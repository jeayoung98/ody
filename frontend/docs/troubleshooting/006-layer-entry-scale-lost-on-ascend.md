# 006. 겹을 파고들었다 떠오르면 줌아웃이 안 된다

- 이슈: S15P21A405-271
- 커밋 / MR: `1c0b7e5` · MR !111
- 날짜: 2026-09-12

## 증상

> "레이어 한번 들어갔다가 나오면 뷰가 바뀜. 원래는 줌아웃 더 됐는데 한번 들어갔다 나오면
> 줌아웃이 안되고 별 무리가 한눈에 안보임."

처음 켰을 때는 1,094곡이 한 화면에 다 들어오는데, 한 겹 파고들었다 돌아오면 아무리 줄여도
별 몇 개만 흩어져 보인다.

## 증거

줌아웃 한계는 `entryS`(그 겹에 들어온 배율) 기준이라 그 값을 단계마다 찍었다.

```js
const e = window.__odyEngine;
({ layer: e.layer, camS: e.cam.s, entryS: e.entryS, 줌아웃한계: e.entryS * 0.4 });
```

| 단계 | `layer` | `entryS` | 줌아웃 한계(`camS`) |
| --- | --- | --- | --- |
| 처음 L0 | 0 | **3.544** | **1.418** |
| 휠로 확대 → L1 파고듦 | 1 | 41.085 | — |
| 다시 줄여 L0 으로 떠오름 | 0 | **71.189** | **28.476** |

돌아온 L0 의 진입 배율이 **20배**로 올라갔다. 그래서 "최대한 줄인 상태"가 원래보다 20배 확대된
화면이 된다. 줌아웃이 안 되는 게 아니라 **한계선 자체가 올라가 있었다.**

같이 찍어 보니 스택 프레임에는 `cam.s = 71.189`(파고들 때의 확대된 배율)만 있고
`entryS` 는 **아예 저장돼 있지 않았다.**

## 원인

떠오르기는 스택 프레임의 카메라를 복원한다.

```ts
ascend() {
  const p = this.stack.pop()!;
  const c: MapCamera = { ...p.cam, cx: …, cy: … };   // 떠날 때의 확대된 배율 그대로
  this.morph(p.layer, c, p.subset, …, -1);
}
```

그리고 모프가 끝나는 자리에서 진입 배율을 이렇게 잡는다.

```ts
this.entryS = a.cam.s;   // ← 도착 카메라 배율 = 떠날 때 확대돼 있던 배율
```

**파고들 때는 이게 맞다** — 새 겹은 `fitCam` 으로 맞춘 배율로 들어가고 그게 곧 진입 배율이다.
그런데 **떠오를 때는 틀리다.** 떠오르기는 "떠났던 화면으로 돌아가는" 연출이라 도착 배율이
그 겹의 진입 배율이 아니라 **떠날 때 확대해 둔 배율**이다.

`Frame` 에 `entryS` 가 없어서 되살릴 값 자체가 없었다.

## 조치

겹을 떠날 때 **그 겹의 진입 배율을 함께 쌓고**, 돌아올 때 되살린다.

```ts
interface Frame {
  layer: number;
  cam: MapCamera;
  subset: Uint8Array;
  entryS: number;   // ← 추가
}

// descend
this.stack.push({ layer: this.layer, cam: { ...this.cam }, subset: this.subset.slice(), entryS: this.entryS });

// ascend — 모프에 실어 보낸다
this.morph(p.layer, c, p.subset, …, -1, p.entryS);

// 모프 완료
this.entryS = a.entryS ?? a.cam.s;   // 없으면 도착 배율 (파고들 때는 그게 맞다)
```

`goHome` 이 상위 겹 프레임을 새로 쌓는 자리에도 같은 값을 넣었다 — 거기서는 그 겹의
맞춤 배율(`fitCam`)이 곧 진입 배율이다.

**카메라 위치·배율은 건드리지 않았다.** 떠났던 화면으로 돌아가는 연출은 의도한 동작이고,
고친 건 **줌아웃 기준점**뿐이다.

## 확인

| 시나리오 | 결과 |
| --- | --- |
| 처음 L0 | `entryS` 3.544, 한계 1.418 |
| L1 파고든 뒤 스택 | `{ layer: 0, camS: 71.189, entryS: 3.544 }` — 진입 배율이 따로 보존됨 |
| L0 으로 떠오름 | `entryS` **3.544** (복원) |
| 끝까지 줌아웃 | `camS` 1.418 = 한계, **화면 안 1,094 / 상주 1,094** |
| L0 → L1 → L2 → 떠오르기 ×2 | L1 복귀 시 37.61, L0 복귀 시 3.544 — **겹마다 제 값** |

마지막 줄이 핵심이다. 상주곡 1,094개가 **전부** 화면에 들어온다 — 처음 켰을 때와 같다.

## 배운 것

**"어떻게 도착했는지"와 "그 상태의 기준값"은 다르다.** `entryS` 는 이름 그대로 *진입* 배율인데,
모프 완료 코드는 그걸 *도착* 배율로 계산하고 있었다. 파고들기에서는 두 값이 같아서 오래 안 드러났고,
떠오르기에서만 갈라졌다.

되돌아가는 동작(undo·뒤로가기·떠오르기)을 만들 때는 **"무엇을 되돌릴지"를 떠날 때 함께 저장했는지**
확인한다. 여기서는 카메라만 저장하고 기준값을 빠뜨렸는데, 카메라로 기준값을 유추할 수 있을 것처럼
생겨서 (`cam.s` 가 있으니까) 빠진 게 안 보였다.

[005](005-stale-overlay-click-gate.md) 와 같은 계열이다 — 거기서는 "떠 있는가"(플래그)를
"집합이 있는가"(데이터)로 판정했고, 여기서는 "진입 배율"을 "도착 배율"로 판정했다.
**비슷해 보이지만 수명이 다른 값을 대신 쓰면 언젠가 갈라진다.**
