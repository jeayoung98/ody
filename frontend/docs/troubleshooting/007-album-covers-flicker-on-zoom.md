# 007. 줌하면 앨범 커버가 통째로 교체돼 반짝인다

- 이슈: S15P21A405-276
- 커밋 / MR: `a1d4f2c` · MR !121
- 날짜: 2026-09-13

## 증상

> "그 앨범 썸네일이 반짝이는 오류가 있거든?"

**가끔**이라는 게 이 건의 어려운 점이었다. 재현 조건이 안 잡히면 원인도 못 좁힌다.

## 어떻게 쟀나 — 실제 그리기를 가로챘다

커버는 캔버스에 그려지므로 DOM 으로는 셀 수 없다. 커버 스프라이트가 **104×104 캔버스**라는 점을 이용해
`drawImage` 를 감싸서 프레임마다 어떤 스프라이트가 그려졌는지 기록했다.

```js
const P = CanvasRenderingContext2D.prototype;
P.__origDrawImage = P.drawImage;
window.__draws = [];
P.drawImage = function (src, ...a) {
  if (src && src.width === 104 && src.height === 104) window.__draws.push({ t: performance.now(), c: src, camS: e.cam.s });
  return P.__origDrawImage.call(this, src, ...a);
};
```

같은 프레임의 그리기는 1ms 안에 몰리므로 시간 간격(4ms)으로 프레임을 갈라 묶었다.

> 처음엔 `requestAnimationFrame` 으로 상태를 샘플링하려 했는데 **5초에 6프레임**밖에 안 잡혔다.
> 브라우저 패널이 가려지면 rAF 가 멈추는 그 함정이다 ([003](003-raf-paused-silent-test-failure.md)).
> 그리기 후킹은 프레임이 실제로 돌 때만 기록되므로 그 함정을 타지 않는다.

## 증거

| 상황 | 커버 수 | 구성 변화 |
| --- | --- | --- |
| 정지 (5프레임) | 7 고정 | **0** |
| 배율 13.9 → 21.8 | 7 → 7 | 5개 나가고 5개 들어옴 |
| 배율 21.8 → 34.2 | 7 → 7 | **7개 전부 교체** |

**개수는 그대로인데 내용물이 바뀐다.** 그래서 "사라졌다 나타났다" 로 보인다.
그리고 **정지 상태에서는 전혀 안 흔들린다** — 그래서 "가끔"이었다. 휠을 돌릴 때만 났다.

## 원인

격자 대표곡을 뽑는 칸 크기가 **배율에 반비례**한다.

```ts
const gw = REPRESENTATIVE_GRID_PX / this.cam.s; // 86 / 배율
```

| 배율 | 격자 칸 (월드) |
| --- | --- |
| 13.9 | 6.187 |
| 21.8 | 3.945 |
| 34.2 | 2.515 |

칸이 잘게 쪼개지면 칸 승자가 전부 바뀌고 → `chosen` 구성이 바뀌고 → 그 앞에서 N개를 잘라 쓰니
커버가 통째로 갈린다.

**`weight` 가 전부 0인 것이 증폭시켰다.** 커버는 `weight` 내림차순 상위 N개를 뽑는데 실데이터는
전부 0이라(BACKEND-NOTES B-21) 정렬이 무의미하다. 순서가 `chosen` 삽입 순서에만 달려 있어서
승자가 바뀌면 **순서 전체가 재배열**된다. 붙잡아 주는 앵커가 하나도 없었다.

## 조치

### 1. 히스테리시스 — 있던 커버를 먼저 지킨다

매 프레임 새로 뽑지 않고, 띄우고 있던 곡을 들고 간다. 화면 밖으로 나갔거나 상주가 아니게 된
자리만 새로 채운다.

```ts
let coverIdx: number[] = [];   // 모듈 수준. 겹이 바뀌면 비운다

// ① 있던 커버를 먼저 지킨다
for (const i of coverIdx) if (usable(i) && spaced(i, picked)) picked.push(i);
// ② 남는 자리만 새로 채운다
```

인덱스로 들고 있는 게 중요하다 — 곡은 뒤에 이어붙기만 하므로(`allocate`) 인덱스는 프레임을 건너도 유효하다.

### 2. 겹치지 않게 최소 간격

줌아웃하면 별이 모인다. 들고 있던 커버가 그대로면 서로 겹치므로 화면 좌표 54px 안으로 붙으면
나중 것을 내린다.

### 3. 한 프레임에 한 칸만 채운다

2번 때문에 줌아웃 한 단계에서 **화면 안인데도 3개가 한꺼번에** 내려가고, 그 자리를 즉시 채우니
딴 데서 커버가 우르르 나타났다 — 그게 또 반짝임이었다. 새로 띄우는 건 프레임당 1개로 제한했다.

## 확인

같은 방법으로 다시 쟀다 (줌인 2단계 + 줌아웃 1단계, 70프레임).

| 지표 | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| **한 프레임 최대 동시 교체** | **7** (전부) | **1** |
| 구성이 바뀐 프레임 수 | 줌 단계마다 | 70프레임 중 4번 |
| 정지 상태 | 변화 0 | 변화 0 (유지) |

남은 교체가 정당한지도 확인했다 — 줌인에서 빠진 커버 3개는 **3개 모두 화면 밖으로 나간 것**이었다.
화면을 벗어난 커버가 교체되는 건 맞는 동작이다.

## 배운 것

**캔버스 렌더링 버그는 상태를 샘플링하지 말고 그리기를 가로채라.** rAF 샘플링은 패널이 가려지면
멈춰서 "안정적이다" 라는 거짓 결론을 준다([003](003-raf-paused-silent-test-failure.md)). `drawImage`
후킹은 실제로 그려진 것만 기록하므로 그 함정이 없고, "몇 개가 그려졌나" 가 아니라 **"어떤 것이
그려졌나"** 를 볼 수 있어서 이번처럼 *개수는 같은데 내용이 바뀌는* 증상을 잡아낸다.

그리고 **매 프레임 처음부터 다시 뽑는 선별은 입력이 조금만 흔들려도 결과가 통째로 뒤집힌다.**
여기서는 배율이 바뀌면 격자가 바뀌고, 정렬 키(`weight`)가 상수라 붙잡아 줄 것이 없었다.
이런 자리에는 **직전 결과를 우선 유지하는 규칙(히스테리시스)** 이 정렬이나 임계값보다 값싸고 확실하다.
