# 008. 호버 카드를 한 번 쓰고 나면 별 호버가 영영 안 잡힘

- 이슈: S15P21A405-277
- 커밋 / MR: 이 이슈의 커밋
- 날짜: 2026-09-13

## 증상

호버 카드를 캔버스에서 DOM 으로 옮기면서 "카드 위에 마우스를 올려도 사라지지 않게" 를 넣은
직후에 났다.

1. 별에 호버 → 카드가 뜬다 (정상)
2. 카드 위로 마우스를 옮긴다 → 카드가 유지된다 (정상)
3. 카드의 재생 버튼을 누른다 → 재생·상세 모두 정상
4. 마우스를 딴 데로 옮긴 뒤 **다른 별에 호버** → 아무것도 안 뜬다
5. 그 뒤로는 새로고침 전까지 **어떤 별도** 호버가 안 잡힌다

## 처음 의심한 것 (둘 다 틀렸다)

- **좌표가 틀렸나.** 브라우저 도구의 좌표계(800×600)와 페이지(1024×768)가 달라서 제일 먼저 의심했다.
  `hitTest` 를 직접 불러 보고 배제했다 — 같은 좌표로 별이 **잡혔다**.
- **드래그가 안 풀렸나.** `drag.current` 가 남아 있으면 `onMouseMove` 가 먼저 빠져나간다.
  마우스를 크게 움직여 봤는데 카메라가 안 움직여서(`camMoved: 0`) 배제했다.

## 증거

마우스가 실제로 핸들러까지 닿는지부터 확인했다. 스테이지에 캡처 리스너를 직접 달아 셌다.

```js
window.__mm = 0;
document.querySelector('canvas').parentElement
  .addEventListener('mousemove', e => { window.__mm++; window.__last = [e.clientX, e.clientY]; }, true);
```

호버 한 번 뒤:

```json
{ "mm": 2, "last": [367, 358], "hitAtLast": { "i": 647, "px": 367.9, "py": 358.0, "r": 15 }, "hoverId": null }
```

**마우스는 닿았고, 그 자리에 별도 있는데, `hoverId` 는 null 이다.** 핸들러가 일을 하기 전에
빠져나간다는 뜻이다. 드래그는 이미 배제했으니 남는 건 카드 위인지 보는 플래그 하나뿐이었다.

커서 클래스도 같은 말을 하고 있었다 — 마우스가 빈 우주에 있는데도 `cursor-pointer` 로 굳어 있었다.
`setHover(false)` 가 아예 안 불리고 있었다.

## 원인

카드 위인지를 **플래그로 기억**하고 있었다.

```tsx
// 카드
onMouseEnter={() => onOverChange(true)}
onMouseLeave={() => onOverChange(false)}

// 지도
if (overCard.current) return;   // ← 여기서 영영 빠져나간다
```

`mouseleave` 는 **살아 있는 요소만** 쏜다. 카드가 포인터 밑에서 그대로 언마운트되면
(호버가 풀려 `song` 이 null 이 되는 순간) 나간 적이 없는 채로 `true` 에 굳는다. 한 번 굳으면
`setHover` 가 다시는 안 불리므로 호버가 통째로 죽는다.

재생 버튼을 누르면 이 조건이 잘 맞는다 — 누른 자리가 곧 카드 위이고, 그 클릭이 상세 패널을 열어
`occludedRight` 를 바꾸고, 곧이어 호버가 풀리면서 카드가 사라진다.

## 조치

플래그를 없애고 **매번 다시 쟀다.** 카드는 스테이지의 자식이라 카드 위 `mousemove` 도 스테이지까지
올라온다. 그러니 이벤트의 타깃이 카드 안인지만 보면 된다.

```tsx
if (cardRef.current?.contains(e.target as Node)) return;
```

상태가 없으니 굳을 자리가 없다. 카드가 사라지면 `cardRef.current` 가 null 이 되어 다음 움직임에서
저절로 정상으로 돌아온다.

## 확인

고친 뒤 같은 절차를 그대로 다시 밟았다.

| 단계 | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| 별 호버 | `hoverId: 4530859` | `hoverId: 4530859` |
| 카드 위로 이동 | 유지 | 유지 |
| 재생 버튼 클릭 | 재생됨 | 재생됨 |
| 카드 밖으로 이동 | `hoverId: null` | `hoverId: null`, 카드 제거됨 |
| **다른 별에 호버** | **`null` (죽음)** | **`hoverId: 4891330`, 카드 다시 뜸** |

## 이어진 문제 — 카드까지 가는 길이 비어 있다

플래그를 고친 뒤에도 **카드로 마우스를 옮기면 그냥 꺼졌다.** 이번엔 원인이 달랐다.

카드는 별에서 `gap`(22px) 만큼 떨어져 뜬다. 마우스가 그 틈 위를 지나는 동안에는 별도 아니고
카드도 아니라서 `hitTest` 가 빈손으로 돌아오고, 그 한 번의 `mousemove` 로 카드가 사라졌다.
**카드에 닿기 전에 카드가 없어지는** 구조였다.

별에서 벗어나도 `graceMs`(220ms) 동안은 붙들어 두고, 그 뒤 `fadeMs`(120ms) 에 걸쳐 사라지게 했다.
엔진의 호버는 **다 사라진 뒤에** 푼다 — 먼저 풀면 카드가 따라붙을 자리(`hoverAnchor`)를 잃어서
사라지는 대신 툭 없어진다.

실제로 잰 값:

| | 결과 |
| --- | --- |
| 별 → 틈 → 카드 (400ms 걸려 이동) | 카드 유지, `opacity: 1` |
| 나타남 | 0 → 0.42 → 0.74 → 0.96 → 1 (약 120ms) |
| 사라짐 | 230ms 까지 1 유지 → 0.41 → 0.13 → 370ms 에 제거 |

## 배운 것

**DOM 이 사라질 수 있는 자리에서 `mouseenter`/`mouseleave` 짝을 상태로 들지 않는다.**
`mouseleave` 는 요소가 살아 있을 때만 오는 이벤트라, 떠 있다 사라지는 UI(툴팁·팝오버·드롭다운)에서는
짝이 깨진 채로 굳는다. 포인터가 지금 어디인지는 **필요할 때 다시 재는 쪽**(`contains(e.target)`,
`elementFromPoint`)이 상태로 기억하는 쪽보다 짧고, 깨질 자리가 없다.

그리고 **"마우스가 핸들러까지 오는가"를 먼저 재야 했다.** 좌표계·히트테스트를 의심하며 시간을 썼는데,
리스너를 하나 달아 이벤트를 센 순간 "이벤트는 오는데 처리가 안 된다"로 범위가 한 번에 좁혀졌다.
