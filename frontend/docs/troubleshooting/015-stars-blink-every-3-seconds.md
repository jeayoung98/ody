# 015. 별이 3초마다 사라졌다 나타남 — "다시 불러오는" 것처럼 보임

- 이슈: S15P21A405-479
- 커밋 / MR: `dc41d59`
- 날짜: 2026-09-20

## 증상

1. 지도를 열어 두고 아무것도 건드리지 않는다.
2. 3초쯤 간격으로 별들이 한 번씩 깜빡인다. 어떤 별은 아예 사라졌다가 다시 밝아진다.
3. → 캐시가 있는데도 **데이터를 다시 불러오는 것처럼** 보인다.

## 처음 의심한 것 (틀렸다)

**주기적인 재요청(refetch/poll)을 먼저 의심했다.** 증상이 "재로딩되는 느낌"이었고 3초는
폴링 주기로 흔한 값이다. `refetchInterval` · `setInterval` 을 전부 훑었지만 3초짜리는 없었다
(`use-nearby-users-query.ts` 의 15초가 가장 가까웠고 지도 별과 무관하다).

화면 전체 밝기를 8초간 재 봤더니 **거의 평평했다.**

```
avg 24.07 · min 24.04 · max 24.11 · swing 0.3%
```

전역으로 한 번에 깜빡이는 게 아니라 **별마다 따로** 깜빡인다는 뜻이다. 그래서 네트워크가
아니라 그리는 쪽을 봤다.

## 증거

`draw-map.ts` 의 두 곳이 나왔다.

기억 정리 조건 — `appear()` 안:

```ts
if (seenAt.size > 4000 && t - e.first > 3) seenAt.delete(id);
```

반짝임 함수 — 모든 별에 걸려 있었다:

```ts
function twinkle(id: number, t: number) {
  const dep = 0.05 + (id % 13) / 34;   // 0.05 ~ 0.40
  const spd = 0.5 + (id % 23) / 9;     // 주기 2.1 ~ 12.6초
  return 1 - dep * (0.5 + 0.5 * Math.sin(t * spd + id * 0.7));
}
```

id 1~3000 으로 돌려 본 실제 범위:

```
최저 밝기 배수 0.597 · 주기 2.1~12.6초 · 대상 모든 별 100%
```

배경 별의 기본 알파는 `0.04 ~ 0.13` 이다. 여기에 0.597 이 곱해지면 `0.024` 까지 내려간다.

## 원인

두 갈래가 겹쳤다.

**① `appear()` 의 기억 정리가 지금 그리는 별을 지웠다** — [`draw-map.ts`](../../src/components/map/render/draw-map.ts)

조건이 `t - e.first > 3`, 즉 **"처음 본 지 3초 지났으면"** 이다. `first` 는 그 별이 언제
나타났는지이지 마지막으로 그린 때가 아니다. 그래서 화면에 멀쩡히 떠 있는 별도 3초만 지나면
대상이 됐다. 지워지면 다음 프레임에 `appear()` 가 기억을 못 찾고 `return 0` — 알파 0 부터
`appearMs`(380ms) 동안 다시 밝힌다. **3초 주기는 여기서 나온다.**

의도 자체는 옳았다. `seenAt` 은 무한히 자라면 안 되니 상한이 필요하다. 잣대를 잘못 골랐을 뿐이다.

**② `twinkle()` 이 배경 별까지 걸려 있었다**

깊이 최대 40%, 주기 2.1~12.6초(가운데값이 3초 언저리)다. 도드라진 별(알파 0.42~1.0)에는
"반짝임"으로 읽히지만, 알파 0.04 짜리 배경 별에는 **사라짐**으로 읽힌다.

①이 깜빡임의 주기를, ②가 "없어진다"는 인상을 만들었다.

## 조치

**①** 잣대를 `first`(언제 처음 봤나) → `last`(마지막으로 그린 때)로 바꾸고, 정리를 `appear()`
안에서 빼내 프레임 단위 `forgetStale()` 로 옮겼다. `appear()` 는 그리는 별마다 `last` 를
갱신하므로, 화면에 있는 별은 절대 대상이 되지 않는다. 상한(`memoryCap` 4000)은 그대로 두고
`forgetMs`(10초) 안 그려진 것만 잊는다.

**②** 배경 별 분기에서 `twinkle()` 호출을 아예 뺐다. 도드라진 별도 큰 쪽(`mag >= 0.7`)의
일부(`id % 3`)만 걸리고, 깊이와 주기를 눌렀다. 기준값은 `constants/map.ts` 의 `STAR_TWINKLE` 로
뺐다 — 다음에 조정할 때 그리는 코드를 안 열어도 되게.

## 확인

| 시나리오 | 결과 |
| --- | --- |
| `twinkle()` 최저 밝기 배수 (id 1~3000, 20초) | 0.597 → **0.860** |
| 주기 범위 | 2.1~12.6초 → **7~13초** |
| 걸리는 별 비율 | 100% → **약 10%** |
| 배경 별 | 걸림 → **호출 제거** |
| `npm run lint` · `npm test` · `npm run build` | 통과 (150 pass / 0 fail) |

**화면으로는 확인하지 못했다.** 확인에 쓴 브라우저에서 `/bff/map/songs` 가 401 이라 지도가
안 떴다. 위 수치는 두 함수를 그대로 떼어 Node 로 돌린 값이다. 실제 화면 확인은 로그인된
환경에서 한 번 더 필요하다.

## 배운 것

**"다시 불러오는 것 같다"는 인상을 네트워크로 단정하지 않는다.** 전역 밝기를 몇 초 재 보면
전역 현상인지 별마다 따로인지가 바로 갈리고, 그 한 번으로 네트워크와 렌더 중 어느 쪽인지 좁혀진다.

그리고 **캐시·LRU 조건에 `first` 를 쓰면 대개 틀린다.** "언제 처음 봤나"가 아니라 "마지막으로
쓴 게 언제인가"가 잣대다. 지금 쓰고 있는 항목이 지워지는 코드는 이 혼동에서 나온다.
