# 016. 인솔자·동승자 헬멧에만 프로필 사진이 안 뜸 — `<img>` 가 먼저 받아 둔 사진은 캔버스가 못 쓴다

- 이슈: S15P21A405-676
- 커밋 / MR: !587
- 날짜: 2026-09-25

## 증상

1. 주변 사람 패널이나 프로필에서 사람을 골라 **따라가기**를 누른다.
2. 우주선 창에 그 사람 사진이 안 뜨고 절차적 얼굴이 뜬다. 내가 인솔자일 때 뒤에 매달린 동승자도 같다.
3. 그런데 **지도에서 처음 보는 사람**의 헬멧에는 사진이 멀쩡히 든다.

## 처음에 짚은 원인 (틀림)

인솔자 정보(`useFollowStore.leaderImageUrl`)가 비어서 그런 줄 알았다. 따라가기 요청(`use-ride-mutation`)이 `target.imageUrl` 을
스토어에 넣고, `map-view` 가 그걸 `NearbyUser` 로 만들어 `startFollow` 에 넘기는 길을 다 읽었는데 값이 빠지는 자리가 없었다.
동승자 쪽은 정말 사진이 없었지만(알림에 `imageUrl` 이 없다, BACKEND-NOTES A-85) 고치고 나서도 인솔자 창은 비어 있었다.

## 실제 원인 (추정 — 코드로 짚었고 브라우저 실측은 못 했다)

캔버스에 그릴 사진은 `lib/avatar-photo` 가 `crossOrigin="anonymous"` 로 받는다 — 캔버스가 오염되면 `toDataURL` 을 쓰는
자리가 터지기 때문이다. 그런데 따라가기 대상은 **누르기 전에 반드시 패널에서 봤다** — 주변 사람 카드·프로필의
`<Avatar>` 가 같은 주소를 **CORS 없이** `<img>` 로 먼저 받는다. 브라우저는 그 응답을 캐시에 넣고, 같은 주소를 CORS 로
다시 달라고 하면 캐시에서 꺼내 주는데 **CORS 없이 받은 응답에는 `Access-Control-Allow-Origin` 이 없다.** 그래서 캔버스용
요청이 거부되고 `failed` 에 굳는다 — 이 모듈은 실패를 주소 단위로 굳히므로 그 뒤로는 영영 절차적 얼굴이다.

지도에서 처음 보는 사람은 캔버스가 먼저 받으니 CORS 응답이 캐시에 들어가고, `<img>` 는 CORS 응답도 잘 쓴다. 그래서
그쪽만 멀쩡했다. 인솔자·동승자가 "유독" 안 됐던 이유가 이 순서 차이다.

## 조치

`photoFor` 를 세 단계로 — CORS → 주소에 `?cors=1` 을 붙여 캐시를 비켜 다시 CORS → 그래도 안 되면 CORS 없이.
세 번째 단계는 캔버스를 오염시키지만, 프로필 사진이 들어가는 캔버스(지도·`HelmetAvatar`)를 읽는 코드는 없다.
`toDataURL` 을 쓰는 건 전부 앨범 커버 캔버스(`coverFor` 계열)다.

## 확인하는 법

개발자도구 Network 에서 사진 주소를 찾는다. 첫 요청(Type: img, `Origin` 헤더 없음)은 200 인데 두 번째 요청(같은 주소,
Request Headers 에 `Origin`)이 `(blocked:cors)` 로 실패하고 콘솔에 `No 'Access-Control-Allow-Origin' header` 가 찍히면
이 문제다. 고친 뒤에는 `?cors=1` 이 붙은 세 번째 요청이 200 으로 와야 한다.

## 교훈

- 같은 그림을 **`<img>` 와 캔버스가 나눠 그리면** 누가 먼저 받았는지가 결과를 가른다. 캐시는 CORS 모드를 키에 안 넣는다.
- "이 사람만 안 된다" 는 데이터가 아니라 **경로 순서**일 수 있다. 값이 어디서 빠지는지 세 번 읽기 전에 네트워크 탭을 본다.
