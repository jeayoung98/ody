## B. 선정 규칙 유닛 — 저장소 없이 검증한다

`NeighborSelection` 은 순수 함수라 합성 후보만으로 전부 검증된다. 조회 mock 도 필요 없다.

## E. 두 진입점 일치 — SC-006

**이 기능의 핵심 검증이다.**

| # | 방법 | 기대 |
| --- | --- | --- |
| E1 | 같은 조회 mock 위에서 곡 상세의 `neighbors` 와 주변 탐색의 `neighbors` 를 비교 | **곡 집합과 순서가 완전히 같다** |
| E2 | 곡 상세 응답 | `lowSimilarity` 가 있고 값이 주변 탐색과 같다 |

E1 이 깨지면 규칙이 두 벌로 갈라진 것이다 — FR-023 위반이라 구현을 되돌린다.

## F. 실 DB 통합 — 선행조건 필요

로컬에 pgvector 와 적재된 `music` 이 있어야 한다. 없으면 **미실행으로 적는다.**

```bash
cd backend
./gradlew bootTestRun
```

기동은 `bootRun` 이 아니라 `bootTestRun` 이다.

| # | 확인 | 기대 |
| --- | --- | --- |
| F1 | 곡 기준 조회 | 200, 이웃 <=10, 거리 오름차순 |
| F2 | 같은 요청 5회 | 목록·순서 동일 (SC-003) |
| F3 | 곡 A 의 이웃 B 를 다시 기준점으로 | 독립적으로 동작 (US2) |
| F4 | 같은 곡의 상세 vs 주변 탐색 | 목록 일치 (SC-006, 실데이터) |
| F5 | p95 지연 | **1초 이내** (SC-002). 콜드 1회를 따로 기록한다 |
| F6 | 10곡 미달 비율 | 표본을 모아 기록 (SC-008). 실측 기준값 0/700 — 0 이 아니면 후보 40 재검토 |

운영 서버로 확인할 경우 주소는 `frontend/deploy.sh` 에 적힌 값이다 — `frontend/.env.example` 의 값은 응답하지 않는다.
