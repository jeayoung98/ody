# Phase 1 — 데이터 모델: 판정 상태

**Date**: 2026-09-18 (MR 326 대조 후 갱신) | 스키마 변경 없음

## 저장 계층 — 판정의 정본은 `music.is_unplayable`

운영 실재 확인(2026-09-18): `is_unplayable boolean NOT NULL DEFAULT false`.

| 상태 | `is_unplayable` | `video_id` | 뜻 | 외부 조회 대상 |
| --- | --- | --- | --- | --- |
| 미판정 | `false` | `NULL` | 아직 묻지 않았다 | **예** |
| 재생 가능 | `false` | 11자 식별자 | 쓸 만한 영상을 찾았다 | 아니오 |
| 재생 불가 | **`true`** | `NULL` (또는 과거 `'none'`) | 물었고, 쓸 만한 후보가 없었다 | 아니오 |

**이번 변경으로 정본이 옮겨간다.** 지금까지는 `video_id = 'none'` 이 재생 불가를 뜻했다. 앞으로는 플래그가 정본이고, 표시값은 쓰지 않는다.

### 현재 불일치 (백필 필요)

| | 행 수 |
| --- | --- |
| `video_id = 'none'` | 560 |
| `is_unplayable = true` | **0** |
| 둘 다 | **0** |

두 표시가 완전히 어긋나 있다. 필터를 플래그 기준으로 바꾸기 **전에** 백필해야 560곡이 되살아나지 않는다.

## 상태 전이

```
        미판정
           │
           ├── 외부 조회: best 있음 ─────────────→ 재생 가능      [최종]
           ├── 외부 조회: !playable && !retryable ─→ 재생 불가      [최종]
           ├── 외부 조회: retryable ──────────────→ 미판정 유지
           ├── 시간 초과·연결 실패 ───────────────→ 미판정 유지
           └── 판정을 가릴 수 없음 ────────────────→ 미판정 유지   ← FR-003
                                                        │
        재생 불가 ──── DATA 삭제 배치(일/주) ────────→ 행 자체가 사라짐
```

- **되돌아가는 전이는 없다.** 값이 생기면 다시 묻지 않고 덮어쓰는 질의도 없다.
- 실패와 "없음"은 다르다. 실패로 아무것도 기록하지 않는 것이 의도된 동작이다.
- **마지막 전이는 백엔드 밖이다.** 삭제 후 그 곡은 존재하지 않으며, 그때의 응답은 FR-008 로 남아 있다.

## 판정 주체의 이동 — 이번 변경의 전부

| | 지금 | 이후 |
| --- | --- | --- |
| 후보 없음을 누가 정하나 | 외부 서비스 (videoId 자리에 표시값) | **백엔드 어댑터** (`playable`·`retryable` 로 판정) |
| 어디에 기록되나 | `video_id = 'none'` | **`is_unplayable = true`** |
| 클라이언트가 받는 값 | `"none"` | `"none"` (읽기에서 번역, 동일) |
| 전이 규칙 | 위와 같음 | 위와 같음 |

## 응답 계층 — `videoId`

| 저장 상태 | 응답 `videoId` | 프론트 해석 |
| --- | --- | --- |
| 미판정 | `null` | `unsearched` — 다시 물어본다 |
| 재생 가능 | 11자 식별자 | `found` — 재생한다 |
| 재생 불가 | `"none"` | `notFound` — 안내하고 다시 묻지 않는다 |
| **삭제됨** | 결과에서 누락 | **미정 (FR-008)** — 지금은 `unsearched` 로 잘못 읽힌다 |

앞 세 줄은 현재와 같다. **그 세 줄이 바뀌지 않는 것이 SC-001 이다.** 네 번째 줄이 삭제 결정으로 새로 생겼다.

## 검증 규칙

- 외부 조회가 실패한 곡에 플래그가 서서는 안 된다(FR-002).
- 판정을 가릴 수 없는 응답에 플래그가 서서는 안 된다(FR-003).
- 같은 곡을 반복 조회할 때 판정이 바뀌어서는 안 된다 — 첫 판정이 최종이다.
- 전환 전후로 세 상태의 응답 표현이 같아야 한다(FR-004).
- 백필 후 `is_unplayable = true` 행 수는 최소 560 이어야 한다(FR-005).
