# Research: 직접 그린 별자리 기반 플레이리스트 생성

**Date**: 2026-09-23 · **Spec**: [spec.md](./spec.md)

## R1. 회전 탐색이 필요한가 — 운영 실측 (595 T048)

2026-09-23 14:24 운영(`backend-blue`, 595 배포 직후)에서 고양이 템플릿 3종을 `generate` 했다.

| 템플릿 | 곡 수 | 중복 | fitError | `layout` 과 좌표 차 | 응답 |
| --- | --- | --- | --- | --- | --- |
| sitting | 23 | 없음 | 0.0008 | 0 (순서 동일) | 8.91 s (첫 호출) |
| sketch | 18 | 없음 | 0.0005 | 0 | 0.16 s |
| loaf | 17 | 없음 | 0.0007 | 0 | 0.17 s |

`findNearestMusicByPc12` 의 `EXPLAIN ANALYZE`: `Index Scan using music_l1_gist`, 0.73 ms.

- **Decision**: 회전·이동·배율을 **탐색하지 않는다.** 사용자 그림의 방향을 그대로 두고, 중심을 곡 분포 상자 중심에, 크기는 595 의 `SCALES` 4단계 중 오차 최소를 쓴다(템플릿과 같은 경로).
- **Rationale**: 재생 가능한 곡 465만 개가 pc1/pc2 평면을 빽빽이 덮는다. 어느 방향으로 놓든 점마다 오차가 반폭의 0.1% 수준이라 회전으로 얻을 것이 없다. 방향을 유지하면 결과 별자리가 사용자가 그린 방향과 같아 비교 화면도 자연스럽다.
- **불변성(FR-008·FR-014)은 탐색이 아니라 점수로 보장한다** — R2.
- **Alternatives**: 회전 12단계 × 배율 4단계 탐색(KNN 960회) — 실측상 이득 없음, 지연만 12배. 기각.

## R2. 모양 일치도 점수 — 이동·회전·균일 배율 불변, 반사 제외

- **Decision**: 2D Procrustes 거리. 두 점열(사용자 그림, 결과 별자리)을 각각 중심 이동 → 크기(프로베니우스 노름) 1 로 맞춘 뒤, 복소수로 보고 `a = Σ conj(u_i)·v_i` 를 구한다. 최적 회전 후 잔차는 `d = sqrt(2 − 2|a|)` (0 = 같은 모양, 최대 √2). **점수 = round(100 · max(0, 1 − d))**.
- **Rationale**: 복소수 곱은 회전만 표현하므로 반사가 자동으로 빠진다(FR-008 "좌우 반전은 다른 모양"). 중심·노름 정규화로 이동·배율이 빠진다. 닫힌 식이라 반복·난수가 없어 결정적이다(FR-012). 점 i 는 곡 i 와만 비교한다(FR-009).
- **Alternatives**: 595 `fitError` 를 그대로 점수화 — 상자 반폭 기준이라 사용자 그림과의 모양 비교가 아니고, 회전 불변도 아니다. 기각. 곡선 거리(Fréchet) — 순서 대응이 이미 고정이라 과함.

## R3. 품질 단계 경계

- **Decision**: `HIGH` ≥ 90 · `MEDIUM` ≥ 70 · `LOW` < 70. 코드 상수, `ponytail:` 주석으로 근거와 조정 경로를 단다.
- **Rationale**: 점수 90 은 `d = 0.1` — 점들이 그림 크기의 약 10% 만큼 흩어진 수준이라 눈으로 같은 모양이다. 70 은 `d = 0.3`(약 30%)로 윤곽이 무너지기 시작한다. R1 실측상 결과 대부분은 `d ≈ 0.001`(점수 100)이므로 `LOW` 는 드물 것으로 예상한다 — 그래도 FR-015·SC-006 은 유지한다.
- **검증**: 단위 테스트에서 삼각형·사각형·별·지그재그에 σ=0.03 / 0.15 / 0.5(도형 RMS 반지름 대비) 잡음을 줘 단계가 HIGH / MEDIUM / LOW 로 갈리는지 확인한다(SC-007 대용). 처음 잡은 0.2 는 예상 점수 ≈72 로 MEDIUM/LOW 경계에 너무 가까워 0.15 로 낮췄다.
- **Alternatives**: 운영 로그로 분포를 본 뒤 정하기 — 배포 전 기준이 없으면 SC-006 을 테스트할 수 없다. 로그(R6)로 사후 조정.

## R4. 첫 호출 8.9 s (콜드 상자)

- **Decision**: `findPc12Bounds` 를 `ApplicationReadyEvent` 에서 **별도 데몬 스레드**로 미리 읽어 캐시에 채운다. 실패하면 WARN 로그만 남기고 첫 요청 때 다시 읽는다(기존 동작).
- **Rationale**: 백분위 2개가 465만 행을 정렬해 8.9 s 걸린다. SC-001(모두 10 s 안)에 거의 닿는다. 메인 스레드에서 돌리면 Blue-Green 헬스체크가 늦어지므로 비동기로 둔다. Java 17 이라 가상 스레드는 없다 — 평범한 데몬 스레드 1개.
- **Alternatives**: 상자 값을 상수로 박기 — 곡 데이터가 바뀌면 조용히 틀린다(헌법 IX). `TABLESAMPLE` 로 근사 — 결과가 요청마다 달라질 수 있어 FR-012 와 충돌. 기각.

## R5. 입력 좌표 규약

- **Decision**: 요청 좌표는 **캔버스 기준 0~1 정규화**, x 오른쪽 · y 아래(캔버스 그대로). 서버가 y 를 뒤집고 중심·최대 절댓값 1 로 정규화해 템플릿과 같은 -1~1·y 위 좌표로 만든다.
- **Rationale**: FE 는 클릭 위치를 캔버스 크기로 나누기만 하면 된다. 0~1 이라 "거의 같은 자리" 판정 기준을 캔버스 비율로 정할 수 있다 — bbox 긴 변 < 0.02 면 모양 없음(FR-016 입력 모양 오류).
- **Alternatives**: px 그대로 — 캔버스 크기마다 기준이 달라진다. y 위 좌표 — FE 가 뒤집어야 하고 틀리면 결과가 상하 반전된다(반사라 점수는 낮게 나오지만 원인이 안 보인다).

## R6. 제한 시간·관측

- **Decision**: 서버 쪽 추가 타임아웃은 두지 않는다. FE 가 요청 타임아웃 10 s 로 "처리 실패"를 띄운다. 서버는 `[Artwork] 그림 매칭 points={} score={} quality={} ms={}` 를 INFO 로 남긴다.
- **Rationale**: 캐시가 찬 뒤 20점 = KNN 최대 80회 × ~1 ms. R4 로 콜드가 사라지면 서버가 10 s 를 넘길 경로가 없다. 타임아웃 코드는 쓰일 일 없는 복잡도다.
- `ponytail:` KNN 이 느려지면(인덱스 미사용 등) 서버 타임아웃보다 먼저 EXPLAIN 을 본다.
