# Feature Specification: 직접 그린 별자리 기반 플레이리스트 생성

**Feature Branch**: `backend/feat/S15P21A405-598-drawn-constellation-playlist`

**Jira**: S15P21A405-598

**Created**: 2026-09-23

**Status**: Clarified — plan 은 595 배포 후 실측(T048) `fitError` 가 나오면 시작한다 (품질 경계값 근거)

**Input**: 사용자가 웹 화면 캔버스에 점을 순서대로 찍어(최소 3, 최대 20개) 입력 순서대로 직선 연결된 별자리를 만들고, 생성 버튼을 누르면 시스템이 음악 공간에서 이동·회전·균일 확대/축소(좌우 반전 제외) 후 모양이 가장 비슷한 음악 배치를 찾아 점 하나당 서로 다른 곡 한 곡을 대응시킨다. 점 입력 순서 = 연결 순서 = 재생 순서. 결과를 미리 듣고 플레이리스트로 저장한다.

## Clarifications

### Session 2026-09-23

- Q: 최선의 배치가 품질 "낮음"(기준 미달)이면 결과를 보여주고 저장까지 허용하나? → A: 보여준다. "낮은 품질" 경고를 붙이고 미리 듣기·저장을 모두 허용한다. 성공 표시(높음·보통의 완료 표시)는 하지 않는다.
- Q: 같은 그림으로 생성을 다시 누르면 같은 결과인가, 다른 배치인가? → A: 항상 같은 결과. "다른 결과 보기"는 두지 않는다 — 다른 결과를 원하면 그림을 고친다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 별자리를 그려 곡 배치를 받는다 (Priority: P1)

사용자가 별자리 그리기 화면에서 캔버스를 클릭해 점을 하나씩 찍는다. 점이 찍힐 때마다 직전 점과 직선으로 이어진다. 3개 이상 찍으면 생성 버튼이 켜지고, 누르면 시스템이 그린 모양과 비슷하게 놓인 곡들을 찾아 결과 별자리와 곡 목록(점 순서대로)을 보여준다.

**Why this priority**: 기능의 핵심 가치다. 이것만 있어도 "내가 그린 모양의 음악"을 받아볼 수 있다.

**Independent Test**: 점 5개를 찍고 생성 → 곡 5개가 서로 다르고, 곡 목록 순서가 점 순서와 같으며, 결과 별자리 좌표가 그 곡들의 별자리 배치 좌표와 같은지 확인.

**Acceptance Scenarios**:

1. **Given** 빈 캔버스, **When** 점 2개를 찍는다, **Then** 두 점이 직선으로 이어지고 개수 표시가 `2 / 20`, 생성 버튼은 비활성이다.
2. **Given** 점 3개, **When** 생성 버튼을 누른다, **Then** 처리 중 상태가 보이고, 제한 시간 안에 곡 3개로 된 결과가 나온다.
3. **Given** 점 20개, **When** 캔버스를 다시 클릭한다, **Then** 점이 추가되지 않고 최대에 도달했음을 알린다.
4. **Given** 결과가 나온 상태, **Then** 사용자 그림과 결과 별자리가 나란히(또는 겹쳐) 보이고, 모양 일치도 점수와 품질 단계(높음·보통·낮음)가 함께 표시된다.
5. **Given** 같은 그림을 캔버스의 다른 위치에, 다른 크기로, 회전해서 그린다, **When** 생성한다, **Then** 원래 그림과 같은 품질 단계의 결과가 나온다.

---

### User Story 2 - 그림을 고친다 (Priority: P1)

사용자는 마지막 점을 취소하거나 그림 전체를 지울 수 있다.

**Why this priority**: 클릭 실수를 되돌릴 수단이 없으면 그리기 자체가 성립하지 않는다.

**Independent Test**: 점 4개 → 취소 → 점 3개와 선 2개만 남는지, 초기화 → 0개인지 확인.

**Acceptance Scenarios**:

1. **Given** 점 4개, **When** 마지막 점 취소, **Then** 4번째 점과 3→4 선이 사라지고 표시가 `3 / 20` 이 된다. 다음에 찍는 점은 3번째 점과 이어진다.
2. **Given** 점 3개, **When** 마지막 점 취소, **Then** 표시 `2 / 20`, 생성 버튼이 비활성으로 바뀐다.
3. **Given** 점 여러 개, **When** 전체 초기화, **Then** 점·선이 모두 사라지고 `0 / 20` 이다.
4. **Given** 결과가 나온 상태, **When** 그림을 고친다, **Then** 이전 결과는 무효가 되어 저장할 수 없고, 다시 생성해야 한다.

---

### User Story 3 - 결과를 듣고 플레이리스트로 저장한다 (Priority: P2)

사용자가 결과 곡을 점 순서대로 미리 듣고, 마음에 들면 플레이리스트로 저장한다. 저장한 플레이리스트를 나중에 열면 같은 곡 순서와 같은 별자리 연결 순서가 보인다.

**Why this priority**: 결과를 남겨야 기능이 서비스 안에서 쓰인다. 다만 P1 만으로도 결과 감상은 가능하다.

**Independent Test**: 결과 저장 → 플레이리스트 상세를 다시 열어 곡 순서와 별자리가 생성 결과와 같은지 확인.

**Acceptance Scenarios**:

1. **Given** 결과 화면, **When** 미리 듣기를 시작한다, **Then** 1번 점의 곡부터 순서대로 재생된다.
2. **Given** 결과 화면, **When** 저장한다, **Then** 결과 곡 순서 그대로 내 플레이리스트가 만들어진다.
3. **Given** 저장한 플레이리스트, **When** 다시 연다, **Then** 곡 순서와 별자리 연결 순서가 저장 시점과 같다.
4. **Given** 생성만 하고 저장하지 않았다, **Then** 플레이리스트는 만들어지지 않는다.

---

### User Story 4 - 실패 원인을 구분해서 안다 (Priority: P2)

결과를 못 만들었을 때 사용자는 왜 못 만들었는지 — 점이 모자란지, 처리가 실패했는지, 비슷한 배치가 없었는지 — 구분해서 안내받는다.

**Why this priority**: 낮은 품질 결과를 성공처럼 보여주면 기능 신뢰가 무너진다.

**Independent Test**: 세 가지 상황을 각각 만들어 서로 다른 안내가 나오는지 확인.

**Acceptance Scenarios**:

1. **Given** 점 2개, **Then** 생성할 수 없고 "최소 3개" 안내가 보인다 (입력 개수 부족).
2. **Given** 처리 중 오류나 제한 시간 초과, **Then** "처리 실패, 다시 시도" 안내가 보이고 결과는 없다 (매칭 처리 실패).
3. **Given** 찾은 최선의 배치가 품질 기준 미달(낮음), **Then** 결과는 보이되 성공으로 표시하지 않고 "충분히 비슷한 배치를 찾지 못함 — 낮은 품질" 경고를 붙인다. 미리 듣기와 저장은 허용한다 (유사도 기준 미달).

---

### Edge Cases

- 모든 점이 같은 자리(또는 거의 같은 자리)에 찍힘 → 모양이 없으므로 생성 불가, 입력 오류로 안내.
- 점이 한 직선 위에 있음 → 정상 입력. 직선 모양 배치를 찾는다.
- 연속한 두 점이 같은 자리 → 정상 입력. 두 점은 서로 다른 곡이 된다.
- 경로가 스스로 교차 → 정상 입력 (분기만 금지, 교차는 허용).
- 생성 중 다시 생성 버튼 → 중복 요청이 나가지 않는다.
- 생성 중 그림을 고침 → 도착한 결과는 버린다.
- 저장 시 같은 이름의 플레이리스트가 이미 있음 → 기존 플레이리스트 규칙대로 이름 중복 안내.
- 비로그인 사용자 → 기존 플레이리스트 기능과 같이 로그인 필요.

## Requirements *(mandatory)*

### Functional Requirements

**입력**

- **FR-001**: 사용자는 캔버스를 클릭해 점을 순서대로 추가할 수 있어야 한다.
- **FR-002**: 점이 추가되면 직전 점과 직선으로 자동 연결되어야 한다. 그림은 첫 점부터 마지막 점까지 하나의 연속 경로다 (분기·선 편집 없음).
- **FR-003**: 화면에 현재 점 개수와 최대 개수(20)를 표시해야 한다.
- **FR-004**: 점이 3개 미만이면 생성할 수 없어야 한다.
- **FR-005**: 점이 20개면 더 추가할 수 없어야 한다.
- **FR-006**: 사용자는 마지막 점 취소와 전체 초기화를 할 수 있어야 하며, 두 동작 후 연결 순서가 남은 점 기준으로 올바르게 갱신되어야 한다.

**매칭**

- **FR-007**: 시스템은 그린 점 하나당 서로 다른 곡 한 곡을 대응시켜야 한다. 한 결과 안에 같은 곡이 두 번 나오면 안 된다.
- **FR-008**: 비교는 점들의 상대적인 모양으로 해야 한다. 그림 전체를 이동·회전·균일 확대/축소해도 같은 모양으로 취급하고, 좌우 반전은 다른 모양으로 취급한다.
- **FR-009**: 점 사이 대응은 입력 순서로 고정한다 — i번째 점은 i번째 곡과 비교한다.
- **FR-010**: 음악 공간은 지도 1레이어와 같은 2차원 축(pc1/pc2)을 쓰고, 후보는 재생 가능한 곡 전체다.
- **FR-011**: 매칭 판단에 쓰는 곡 위치와 결과 별자리를 그리는 위치는 같은 좌표·같은 별자리 좌표 산출 규칙에서 나와야 한다. 결과 별자리 좌표는 그 곡 집합을 별자리 배치 규칙에 넣은 값과 같아야 한다.
- **FR-012**: 같은 그림(같은 점 좌표·순서)을 다시 생성하면 같은 결과가 나와야 한다. 결과를 바꾸는 방법은 그림을 고치는 것뿐이며, 차선 배치를 따로 보여주는 기능은 두지 않는다.
- **FR-013**: 매칭은 제한 시간 안에 끝나야 하며, 넘기면 처리 실패로 끝낸다. 처리 중에는 진행 상태를 표시해야 한다.
- **FR-014**: 결과에는 0~100 **모양 일치도** 점수와 품질 단계(높음·보통·낮음)를 함께 제공해야 한다. 같은 그림을 이동·회전·확대해도 점수가 같아야 한다.
- **FR-015**: 품질이 기준 미달(낮음)이면 성공으로 표시하지 않고 낮은 품질 경고를 보여야 한다. 결과 확인·미리 듣기·저장은 높음·보통과 똑같이 허용한다.
- **FR-016**: 입력 개수 부족, 입력 모양 오류(점이 한 자리에 몰림), 매칭 처리 실패(오류·시간 초과), 유사도 기준 미달을 서로 다른 안내로 구분해야 한다.
- **FR-017**: LLM 없이 기하 정규화와 유사도 계산만으로 동작해야 한다. 모양 일치도는 "사용자 그림 ↔ 곡 배치"의 기하 비교이며, 회차 주제 AI 채점(548/563, GMS)과 무관하다.

**결과·저장**

- **FR-018**: 결과 화면은 사용자 그림과 결과 별자리를 비교해 보여줘야 한다. 결과 별자리는 선택된 곡의 좌표 그대로, 입력 순서대로 연결한다.
- **FR-019**: 사용자는 결과 곡을 입력 순서대로 미리 들을 수 있어야 한다.
- **FR-020**: 생성만으로는 플레이리스트가 만들어지지 않아야 하며, 사용자가 저장해야 만들어진다.
- **FR-021**: 저장된 플레이리스트의 곡 순서는 점 입력 순서와 같아야 하고, 다시 열어도 곡 순서와 별자리 연결 순서가 유지되어야 한다.
- **FR-022**: 결과가 나온 뒤 그림을 고치면 그 결과는 저장할 수 없어야 한다.

### Key Entities

- **그린 별자리 (Drawing)**: 사용자가 찍은 점 3~20개의 순서 있는 목록. 점은 캔버스 기준 2차원 좌표. 저장하지 않는 일회성 입력.
- **매칭 결과 (Match Result)**: 점 순서대로 대응된 곡 목록(중복 없음), 각 곡의 별자리 좌표, 유사도 점수, 품질 단계. 저장 전까지는 화면에만 있다.
- **플레이리스트 (Playlist)**: 기존 엔티티. 매칭 결과를 저장하면 곡 순서 그대로 하나 생긴다. 새 필드 없음 — 별자리는 곡 순서와 별자리 배치 규칙에서 다시 계산된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 20점 그림 기준 생성 요청의 95%가 3초 안에 결과를 보여주고, 모든 요청이 10초 안에 결과나 실패 안내로 끝난다.
- **SC-002**: 생성된 결과 100%에서 곡이 서로 다르고, 곡 수·순서가 점 수·순서와 같다.
- **SC-003**: 같은 그림을 이동·회전(임의 각도)·확대(0.5~2배)해 그린 입력들의 모양 일치도 점수 차이가 1점 이하다.
- **SC-004**: 결과 별자리 좌표와, 그 곡 목록을 별자리 배치 규칙에 넣은 좌표가 100% 일치한다.
- **SC-005**: 저장 후 다시 연 플레이리스트의 곡 순서가 100% 생성 결과와 같다.
- **SC-006**: 품질 기준 미달 결과가 성공으로 표시되는 경우가 0건이다.
- **SC-007**: 단순 도형(삼각형·사각형·별·지그재그) 기준 입력의 80% 이상이 품질 "보통" 이상을 받는다.

## Assumptions

- 좌표계는 595 에서 머지된 pc1/pc2 고정축을 쓴다 (2026-09-23 확정). 집합 PCA 로 되돌리면 FR-010·FR-011 이 성립하지 않는다 — 곡을 고른 뒤 축이 바뀌어 모양이 풀린다.
- 후보 곡 풀·재생 불가 제외·최근접 조회·분포 상자·곡 선택 규칙은 595 생성기를 그대로 쓴다. 템플릿 생성(`/api/artwork/templates`, `/generate`)의 동작은 바꾸지 않는다.
- 저장은 기존 플레이리스트 생성 기능을 그대로 쓴다. 이름은 기본값(예: `내 별자리 HHmmss`)을 채워 주고 사용자가 바꿀 수 있다.
- 품질 단계 경계값과 점수 환산식은 plan 단계에서 실측으로 정한다. 스펙은 "이동·회전·확대 불변, 0~100, 3단계, 낮음 = 기준 미달"만 고정한다.
- 결과 별자리는 곡의 실제 위치대로 그리므로 사용자 그림과 회전·크기가 다를 수 있다. 비교 화면은 사용자 그림을 결과에 맞춰 정렬해 겹쳐 보여주는 방식을 기본으로 한다.
- 취향 반영, 작품 제출(548) 연동은 이번 범위 밖이다 (다른 결과 다시 뽑기는 Clarifications 에서 제외 확정). 저장된 플레이리스트는 일반 플레이리스트이므로 기존 제출 흐름에는 그대로 쓸 수 있다.
- FE 화면 구현은 FE 파트에 요청한다. 이 저장소 작업(백엔드 브랜치)은 매칭 API 까지다.
